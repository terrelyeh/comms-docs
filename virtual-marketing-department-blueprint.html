虛擬行銷部門 AI Agent 參考架構藍圖

一套可重複部署、再依客戶客製的「AI 行銷部門」。底盤統一(Paperclip 治理 + Hermes 員工 + MCP/Skills 能力),客製只動三個旋鈕。修正版:6 個同層職能、消掉 Digital 重疊傘、補上 Lifecycle 與 Analytics/Ops,並依客戶規模縮放。

📅 2026-06-03 · 修正版 🧑‍💻 AI FDE / 部署者 🏗️ Paperclip · Hermes · MCP
設計原則:照 workflow 拆,不照人類職稱拆

AI agent 的編制不該複製人類組織圖。用三個準則切分,編制自然乾淨。

  1. 一段連貫的 workflow — 輸入 → 產出是一條完整流程。
  2. 一組共用的工具面 — MCP / skills 集中在同一個 agent。
  3. 一種一致的審批風險 — 例如「會花錢」要獨立成自己的審批邊界。
依此原則,舊版的「Digital Marketing」被拆解 —— 它本來就是涵蓋 SEO/付費/email 的傘,跟旗下項目重疊。它真正獨有的價值(量測與追蹤治理)獨立成 Analytics & MarTech Ops,其餘回歸各 owner。
三層架構總覽

治理層管「有哪些員工、各自預算、做得對不對」;員工層是會做事的 agent;能力層是各職能的專業。

層角色工具
治理層主管 / HR / 財務Paperclip(org chart · 預算 · 審批 · 稽核)
員工層各職能 agentHermes(常駐 · 模型不限 · Skills 系統)
能力層各職能專業客製 skills + 客戶 MCP + Claude World Studio MCP

編組關係

Paperclip(治理層:org chart / 預算上限 / 審批 / 稽核) ├── 策略 & 產品行銷 Hermes + 定位 skills (大腦) ├── Organic Growth Hermes + SEO/內容 skills + Ahrefs/Search Console MCP ├── Paid / Demand Gen Hermes + 廣告 skills (預算上限由 Paperclip 鎖) ├── Lifecycle / CRM Hermes + email/自動化 skills + HubSpot/Klaviyo MCP ├── Creative Studio Hermes + 文案/視覺/影片 skills + Canva/Remotion MCP └── Analytics & Ops Hermes + 報表 skills + GA/Amplitude/Supermetrics MCP ▲ 行銷總監(human):最終審核、人類把關
6 職能編制(同層 · 最小重疊)

每個職能 = 一個常駐 Hermes agent,掛上對應 skills 與客戶 MCP。注意每個職能的審批點。

🎯

1 · 策略 & 產品行銷

大腦 · 品牌單一事實來源
職責定位、訊息架構、競品/市場情報、GTM 策略、目標拆解與派 brief
Skillsmessage-guide-* pipeline、competitive-brief、message-guide-review
MCPWeb 研究、Similarweb、文件(Drive / Notion)
輸入→輸出產品 brief / HQ guide / 競品 → 定位卡、Message Guide、季度策略、各職能 brief
審批點對外訊息與策略定稿需人類核可
下游所有職能都吃這份定位,同時是拆解目標、派工的大腦。
🌱

2 · Organic Growth

OWNED / EARNED 一條龍
職責SEO(關鍵字、技術巡檢、on-page)+ 內容(部落格/案例/電子報內容)+ 自然社群
Skillsseo-audit、draft-content、eg-content-repurpose、internal-comms、自建 keyword-research
MCPAhrefs、Similarweb、Search Console、Claude World Studio(trend-pulse / cf-browser)、發布工具
輸入→輸出定位 + 關鍵字機會 → 內容行事曆、SEO 優化內容、自然流量成長
審批點對外發布、網站結構改動需核可
排程每週 SEO 巡檢 + 選題(Hermes cron)
SEO 與 Content 合併,避免「內容行事曆誰擁有」的切割打架。
📣

3 · Paid / Demand Gen

付費需求開發 · 最高風險職能
職責付費搜尋 / 社群、受眾、出價策略建議、A/B、需求開發 campaign
Skillscampaign-plan、自建 ad-copy / audience-research
MCPSupermetrics、Meta / Google Ads(唯讀報表)
輸入→輸出目標 / 預算上限 / 受眾 → 廣告文案、受眾建議、出價建議、成效分析
審批點🚨 實際投放 / 動用預算一律人類執行;agent 只給建議。Paperclip 鎖月預算上限
🔁

4 · Lifecycle / CRM

OWNED AUDIENCE 經營
職責email、nurture 流程、行銷自動化、名單分群、留存 / 再行銷
Skillsemail-sequence、campaign-plan(lifecycle 版)、自建 segmentation
MCPHubSpot、Klaviyo、客戶 CRM
輸入→輸出名單 + 旅程目標 → nurture 序列、自動化流程、留存 campaign、名單健康報告
審批點對外寄送(EDM)前需核可
🎨

5 · Creative Studio

服務全部門的產能
職責文案、視覺 / 設計、影片、品牌素材(供應所有職能)
Skillsyoutube-script、storyboard-generator、remotion、draft-content(copy)
MCPnanobanana(生圖)、Canva、Remotion(render)、NotebookLM、Figma
輸入→輸出各職能 creative brief + 品牌素材 → 文案、圖、影片、成片
審批點對外發布前需核可
共用產能,吃同一份品牌 skill,避免多 agent 風格分裂。
📈

6 · Analytics & MarTech Ops

量測層 · AI 最擅長
職責數據彙整、儀表板、歸因分析、UTM / 追蹤治理、MarTech 串接健康
Skillsperformance-report、dashboard-builder、UTM 指南、ShortLink
MCPAmplitude、Supermetrics、GA、HubSpot(讀)
輸入→輸出各渠道數據 → 統一儀表板、歸因報告、UTM 規範、洞察回饋給策略
審批點多為唯讀分析;追蹤規範變更需協調
把成效回饋給策略,形成閉環。這塊最適合 AI 自動化。
依客戶規模縮放(6 不是魔法數字)

FDE 賣法:baseline 給 6,Discovery 後依客戶縮放 —— 小客戶合併、大客戶展開。

客戶規模agent 數編制
小型 / SMB3策略 / Growth(organic+paid 合)/ Creative+Ops 合
中型6上面六職能
大型 / Enterprise8–10再拆出 Social/Community、Localization、CRO、PR
跨職能協作流程

定位先行;三個渠道引擎共用 Creative 產能;Analytics 統一量測後回饋策略,形成閉環。

策略 & 產品行銷(大腦:定位 + 目標拆解 + 派 brief) │ 定位卡 / Message Guide (品牌單一事實來源) ┌────┼─────────────────┬───────────────┐ ▼ ▼ ▼ ▼ Organic Growth Paid/Demand Gen Lifecycle/CRM (SEO+內容+社群) (付費 · 預算) (email · 自動化) └────────┬──────────────┴───────────────┘ │ 共用 creative brief ▼ Creative Studio(文案 / 視覺 / 影片 → 供應全部門) │ ▼ Analytics & MarTech Ops(統一量測 · 歸因 · UTM 治理) │ 成效回饋 ▼ 策略 & 產品行銷(迭代定位) ◀── 閉環
治理層(Paperclip)與紅線

Paperclip 負責什麼

org chart6 職能 + 回報給「行銷總監(human)」
預算上限每個 agent 設月預算上限,超支自動暫停(Paid / Demand Gen 尤其重要)
審批關卡對外發布、廣告花費、EDM 寄送、網站結構改動
稽核immutable audit log,所有決策與 tool call 可追溯
品牌來源全部產出吃同一份 message guide + .impeccable
幫別人建,特別要顧的四條紅線:
  • 花錢 / 投放絕不自動化 — 一律走人類審批,合約寫清責任歸屬。
  • 資料與密鑰隔離 — 每客戶獨立部署,各自 API key 走 secrets 管理。
  • 成熟度風險 — 工具都還新,先 pilot 一個職能再擴成整個部門。
  • 品牌一致性 — 同一份品牌 skill,避免多 agent 風格分裂。
導入路線

分階段,不要一步到位。先把一個職能跑出成效,再擴編,最後才疊治理層。

Phase 1 · Pilot

單一職能驗證

挑 1 個高價值職能(Organic Growth 或 Analytics/Ops),用 Hermes + 客製 skill 跑出成效。

Phase 2 · 擴編

串起協作流程

加到 3–4 個常駐職能,讓定位 → 內容 → 成效的流程跑起來。

Phase 3 · 治理

疊上 Paperclip

org chart、預算上限、審批、稽核,交付客戶可自行操作的 GUI。

FDE 可重複資產(Starter Kit)
📦

把第一次做的沉澱成模板

之後每客戶 fork 再客製
org 模板6 職能 + 預算 / 審批預設
skill pack6 職能通用 baseline skill,客戶版覆寫
MCP playbook常見平台(HubSpot / GA / Ahrefs / 廣告後台)怎麼接
交接資產Discovery 問卷 + 交接文件模板
你 FDE 真正在賣的不是工具 —— 是「把客戶 know-how 變成 skills + 把流程變成 org / 預算 / 審批設定」的能力。
